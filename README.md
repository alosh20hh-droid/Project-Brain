# Project Brain

عقل مستقل لإدارة المشاريع طويلة المدى من الهدف إلى التنفيذ والتحقق والاستمرار.

## ما الذي ينجزه القلب الحالي؟
الهدف العام يتحول إلى حالة مشروع وخطة وطلب تنفيذ محدود. العمليات الحساسة ترتبط بموافقة مالك محددة وبمعرّف عملية دائم، والمنفذ لا يستطيع اعتماد نتيجته بنفسه. الأدلة تمر عبر متحقق مستقل، والحالة والعمليات والموافقات والنبضات والإيجارات تحفظ في SQLite لاستعادة التشغيل بعد الانقطاع.

المسار الأساسي:
Goal → Research/Plan → Execute → Observe → Verify → Learn/Replan → Persist → Continue

## حدود الأمان
- المنفذ لا يصدق على عمله بنفسه.
- النجاح الذي يتطلب دليلاً لا يقبل بلا دليل سليم وقوة معلنة.
- الأدوات الخارجية لا يسمح لها بتخفيض مستوى خطورتها.
- الدفع والعقود والعمليات الحساسة تحتاج موافقة مالك محددة النطاق.
- الموافقة الحساسة ومعرّف العملية يحجزان ذرياً في التخزين الدائم عند توفره.
- العمليات المحجوزة أو المكتملة لا تعاد بصورة عمياء بعد الانهيار؛ تنتقل للمصالحة.
- حالة المشروع تحفظ خارج سياق النموذج.
- الفشل والرفض يدخلان في إعادة التخطيط.
- هذا المستودع مستقل ولا يعدل أي مستودع سابق.

## الطبقات
- Project Brain: التخطيط، الفرضيات، التجارب، التعلم، إعادة التخطيط والتحقق.
- Control plane adapter: حد تكامل Paperclip.
- Cognition adapter: حد تكامل Nous.
- Execution adapters: منفذات قابلة للتبديل، ومنها حد UFO.
- Persistent runtime: SQLite، السجلات، منع التكرار، النبض، الإيجارات والاسترجاع.

## الاختبارات
GitHub Actions يشغل المجموعة كاملة عند كل دفع ويمكن تشغيلها يدوياً. آخر خط أساس موثق في 26 سبتمبر 2026: **80 اختباراً ناجحاً** على Python 3.11.

## حالة المشروع
قلب النظام واختبارات وحداته وتكامله الداخلي تعمل. محولات Nous وPaperclip وUFO موجودة كحدود تكامل ولا تدّعي أن الخدمات الخارجية نفسها منصبة أو متصلة. الانتقال للإنتاج يتطلب تهيئة مزودي النموذج والمنفذات والمفاتيح وسياسات النشر في بيئة التشغيل المستهدفة.
